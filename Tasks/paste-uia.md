# Hanging double-click in UI Automation editors

The November 9 development revision `c7493b6` moved external editor binding into a supervised process. The previous synchronous implementation at `558633e` could retain the editor directly. The worker checked the last input timestamp both on entry and after reading the field. The first mouse release over the card can change that timestamp without moving the editor caret. Revision `a025636` accounted for this in Office. The release snapshot on main still used strict timestamp equality for UI Automation editors.

On Windows 11 build 26200 with Edge 157.0.4341.46, the unmodified production executable from main promoted the selected card, collapsed the workspace and published the expected Unicode. The selected character stayed in place and both independent fields received zero keyboard and paste events. The qualification build using the original logic recorded `published no-field committed`. In the synchronized private-station test the old comparison rejected a witnessed release before binding with no field and zero deliveries. An initial manually seeded baseline had an incomplete snapshot manifest. All receiver results below use profiles created by the normal clipboard capture command.

The host now validates its existing card input witness for UI Automation and Office. The worker covers startup and field acquisition under the original deadline. A repeated WPF run also caught the system input clock ahead of its mouse hook. The workspace had witnessed the second down, while Windows had already exposed the second release 15 ms later. The host now remembers the outstanding timestamp until its exact event is witnessed or the original deadline expires. The private fixture reproduces that ordering and rejects a different, later local tick. Each side still checks the selection or native focus before delivery. The protocol signature distinguishes workers that support the new guard.

The private fixture exercises both release timings and terminal cancellation for external input, an unobserved transition or missing hooks. The public desktop gesture, clipboard ownership, native shortcut counts, both independent field values, durable position and workspace visibility are observed on the foreground desktop. Edge and the WPF Group receiver each replaced the selected character exactly once on first open and reopen. Read-only, password, changed-field and interrupted-then-restored Edge selections received zero shortcuts and zero pastes. The transaction fixture covers copy only, failed publication and commit, and replacement before delivery.

The visual comparison used the recovered 1920 × 363 workspace and 300 × 200 Floating frame from the original logic and the repaired build. Both pairs matched pixel for pixel. The reviewed workspace shows the same readable paper, hook, rope and collector plaque. The Floating card keeps the Return button, text and close control. The [source-bound checklist](../tests/compatibility/fluent/evidence/uia-card-paste.json) records the extent of this review.

The final interactive gate passed 34 CTest cases and all eight restored Production observations. They were `edge.first`, `edge.reopen`, `edge.readonly`, `edge.password`, `edge.change`, `edge.interrupt`, `custom.first` and `custom.reopen`. Ten additional independent WPF launches on Qualification completed all 20 first-open and reopen gestures. The final source fingerprint was `40bc729a68af8a7a29e67b9ca9c3c2aa04b28633bd4bc16c4c583d10e13ccade`. The measured Production `ClipRope.exe` SHA-256 was `b77370057d234d1d21b304c095e60c8c13cb7060b8886dda41b4ba8e36929aa0`. The generated `build/test-receipt.json` contains the remaining payload hashes and the full list of passing CTest names.
