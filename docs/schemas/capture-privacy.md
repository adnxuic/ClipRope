# Per-profile capture preferences and diagnostics

The optional `capture_preferences` SQLite table stores a single row (ID 1) containing the pause flag and newline-delimited UTF-8 executable basenames. Saving the first preference creates the table and row in one transaction. Existing v2 profiles default to active capture with an empty list. The v2 reader can ignore this additive table. A backup includes it. A damaged preference pauses desktop capture until valid preferences are restored. The Settings Center reports the damaged policy.

Up to 64 names are accepted. Path separators, control characters and wildcard patterns are rejected. The host applies Windows ordinal case-insensitive matching to the executable basename. A capture with an unknown source is skipped when an exclusion list is active. Changing policy invalidates pending admission. The host advances the sequence baseline so an earlier clipboard value does not enter history when capture resumes.

The Windows local-history marker and monitor-processing exclusion block payload extraction. A cloud-upload-only exclusion permits local capture. The desktop and headless capture entry points both apply the persisted policy.

The storage page reports the active data folder and its disk usage. [Storage settings](../decisions/0019-appearance-and-profile-location.md)

Start the desktop with `--export-diagnostics-on-exit` to write the current session's aggregate counters to `diagnostics.txt` in the selected profile on exit. Version 2 includes separate capture and command counters for stale bindings, storage contention and storage failures, plus post-commit notification failures and target verification timeouts. The report contains no clipboard body, registered-format name, executable name, entry ID or file path. The opt-in developer transcript records controlled IDs, outcomes and geometry independently.

The [offline test](../../tests/integration/offline.cpp) verifies that a loopback connection succeeds from its control process and that a guarded canary stops before Winsock initialization. The same process-tree guard covers normal headless capture, its worker and a fresh recall process. Unicode and HTML survived the overwrite and source exit byte for byte while Winsock was unavailable to those processes. The host machine's network remained connected.

Before the read-only Settings Center, on the reference Windows 11 desktop, `P6-04.privacy_controls` used the resident application and its real Settings controls with a separate producer on a private window station. It verified pause, a rejected path in the exclusions editor, an executable exclusion across restart, two local exclusion markers, a cloud-only marker, cancellation during delayed extraction, an actual failed read, user-triggered export and an independent restore from disk. The stored sample contained a private-looking absolute path. Neither the export nor the development transcript contained the tested markers. A one-rope clear preserved another rope and Floating. An all-rope clear preserved only Floating. Explicit confirmed deletion removed the last card.
