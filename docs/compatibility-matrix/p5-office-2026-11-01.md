file version 16.0.20527.20112. The Release x64 test completed all 24 routes
in 35.48 seconds. Excel was the source and destination for the first four
rows. PowerPoint was the source and destination for the last four. All eight
source objects came from the checked-in synthetic documents. [Exact offered,

### Representations and visible fidelity

The actual UI projection labeled the three Excel cell cases **HTML · Text ·
RTF · partial**. The graphics cases showed **Image · partial**. Each image
was a registered PNG on `TYMED_ISTREAM`. A picture in the destination had
Office shape type 13. Unverified native BIFF, PowerPoint shape/slide packages,
OLE embeddings and other unsupported representations were omitted. The
inventory records every offer's format name/ID, medium, aspect, index and
adapter outcome. It also records the formats that could actually be read from
the published object and the manifest of the resident entry used for recall.

For the four pasteable picture cases the test compared the native and
restored renderings after normalizing each to a 32 × 32 grid and compositing
alpha onto white. Mean absolute RGB-channel error on the 0–255 scale was
8.65 for the Excel chart, 10.70 for the text box, 13.29 for the group and
13.25 for the PowerPoint chart. Warm and cold values agreed. Differences in
padding, typography or rendering can change this metric; the table records
geometry and actual editable-object checks separately.

### How the routes were measured

1. The controller launched an isolated Office source process on a private
   window station. It verified both process identity and the unique test
   document before issuing Office commands. The source used the Ribbon Copy
   command while the actual desktop ClipRope listener was running. All eight
   objects were admitted by normal local-history policy. No matrix row needed
   the explicit-import fallback.
2. Each native destination received one application paste. Excel used
   `Worksheet.Paste`, individual PowerPoint objects used `Shapes.Paste`, and
   the full-slide case used `Slides.Paste` in the slide sorter. Each object's
   history routes used that same destination command on a fresh document.
   The P6 requalification controller waits for the intended PowerPoint
   destination, Paste command availability and the expected clipboard owner
   before issuing its single paste. The PNG-only slide-sorter case also
   exercises the command when the Ribbon reports it disabled and records the
   resulting rejection or insertion count.
3. A synthetic overwrite was verified before each recall. Its exclusion
   marker prevented it from entering history. The controller invoked the
   resident workspace's rope-head command, checked the bound ID, successful
   publication and commit, and inspected readable media while ClipRope served
   paste requests. The destination performed the paste independently.
4. After stopping the producing Office process and the source-time ClipRope
   processes, the controller started a new Office process on a blank document
   and reopened each profile in a fresh ClipRope process. For every saved
   representation, format, medium, byte length and SHA-256 agreed between
   the warm publication, the reopened manifest and the cold publication.

P0's earlier Excel `Range.Copy` measurement used an explicit adapter probe
on an object which offered a local-history exclusion marker. This matrix's
ordinary Ribbon Copy produced passive admissions on this Office build.
[P0 Excel measurement](p0-excel-range.md)

### Reproduce

Install desktop Excel and PowerPoint, close other PowerPoint instances, and
use the Windows build environment. The presentation controller uses only
the synthetic instance's native document window or verified running Office
object. The checked-in fixtures need no Python installation to run.
[Fixture generator](../../tests/compatibility/office_matrix_fixtures/generate.py)
· [Office controller](../../tests/compatibility/office_matrix.ps1)
· [Windows build guide](../developer/build.md)

```powershell
cmake -S . -B build/p5-office -G "Visual Studio 17 2022" -A x64 -DCLIPROPE_DESKTOP_PROBES=ON -DCLIPROPE_TEST_OFFICE_MATRIX=ON
cmake --build build/p5-office --config Release
ctest --test-dir build/p5-office -C Release -R P5-06.office_matrix --output-on-failure
```
