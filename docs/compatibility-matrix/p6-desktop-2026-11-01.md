# Desktop and integrity qualification

The November 1, 2026 qualification used Windows 11 25H2 x64 build 26200.9711, Release x64 and one 1920 × 1080 display at 120 DPI. The interactive application and external test fields ran at Medium integrity. Synthetic profiles supplied every card and document. A separate run started the gesture caller with a restricted Low-integrity primary token. The test host and the installable application share their window procedures and rendering code. Only the qualification host has the optional fault controls used to exercise failed publication and history commits. [Build configuration](../developer/build.md) · [Display inventory](../../tests/compatibility/overlay.md)

## Native window messages and resource recreation

These tests used a private Windows window station, the real workspace or resident executable, and isolated synthetic history. They replayed the following notifications without changing the running workstation's session or display configuration. [Notification fixture](../../tests/compatibility/desktop_notifications.cpp)

| Event | Observed result |
| --- | --- |
| Per-monitor DPI notifications at a negative origin | `WM_DPICHANGED` changed the real workspace rectangle at (−600, −30) through 96, 144, 192 and 96 DPI. The same entry remained visible, physical paper height scaled on each transition, the paper center belonged to the native region and the transparent gap stayed outside. |
| Missing saved monitor and lost work area | A persisted off-screen Floating layout reopened inside the available work area. The fixture moved the existing HWND to (−24000, −15000). A reconnect event for a different session left it there. The current session's reconnect moved it fully inside the work area. |
| Session disconnect, reconnect, lock and unlock | Disconnect canceled a press bound before the session boundary. Its follow-on double-click changed neither the clipboard sequence nor the workspace visibility. Unlock preserved an independently visible Floating card and a hidden workspace. |
| Suspend and resume | Windows accepted the resident HWND's explicit suspend/resume subscription on the private window station. The fixture replayed `PBT_APMSUSPEND` and `PBT_APMRESUMEAUTOMATIC`. The candidate recorded both messages, preserved the hidden workspace and reachable Floating card, captured the next independent OLE publication once, and released the subscription on shutdown. These checks passed three consecutive runs. |
| Direct2D and compositor resources | `WM_DWMCOMPOSITIONCHANGED`, session reconnect and resume discarded target-dependent resources. The external test requested native painting through `PrintWindow` because the private station has no active compositor. The successful Direct2D render-target creation count increased after each recovery. The production `D2DERR_RECREATE_TARGET` branch shares the same disposal path. |

The reference hardware had one active monitor. A physical two-monitor DPI transition, hot-unplug, a real remote-desktop disconnect and reconnect, an actual graphics-driver reset, and Medium-to-UAC-High delivery remain unmeasured. The cross-integrity row measures the tested Low-to-Medium boundary. [Native delivery implementation](../../src/platform_win/delivery.cpp)

The reference installation is Windows 11 Home. Microsoft's Remote Desktop host instructions require Windows Pro, so a physical RDP reconnect requires another host. On this machine `powercfg /a` reported S0 low-power idle (Modern Standby) and hibernation available. Firmware did not provide S3 sleep. [Microsoft Remote Desktop host requirements](https://support.microsoft.com/en-us/windows/experience/connectivity-networking/how-to-use-remote-desktop)

## Reproduction

Configure and build the `windows-qualification` preset. The two notification suites use the station launcher. The remaining commands require a reserved, unlocked desktop and synthetic clipboard content. Run them sequentially.

```powershell
$out = 'build/release/qualification'
ctest --test-dir $out -C Release -V -R 'P6-06\.(session_notifications|dpi_notifications|higher_integrity)'
& "$out/Release/cliprope_surface_test.exe" --physical (Resolve-Path "$out/Release/cliprope_overlay_probe.exe")
ctest --test-dir $out -C Release -V -R 'P0-05\.desktop_delivery|P2-05\.desktop_flow|P2-04\.desktop_tray|P3-03\.floating_desktop'
```

## Manual hardware sleep and wake

The listener uses `RegisterSuspendResumeNotification` with `DEVICE_NOTIFY_WINDOW_HANDLE`. If Windows declines the registration, the qualification receipt reports `power subscription-unavailable` and ordinary clipboard monitoring continues. A successful qualification receipt records `power subscribed`, the message kind and UTC Windows FILETIME for each suspend/resume, and `power unsubscribed` after releasing the handle. [Windows subscription API](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registersuspendresumenotification) · [Modern Standby desktop notifications](https://learn.microsoft.com/en-us/windows/compatibility/desktop-activity-moderator)

For an interactive run, use an unlocked test desktop, the Release qualification build with desktop probes enabled, PowerShell and Python 3. Close any other ClipRope instance. Prepare the commands before capture starts so that copying instructions does not generate extra entries.

1. From the repository root, launch the candidate with a fresh profile and receipt file. Wait for `ready` in the receipt. In Notepad, type and copy only `ClipRope sleep seed` once. Drag its workspace card off the rope. Verify the receipt shows `detach <id> committed` and `floating <id> <rectangle>`. Hide the workspace and leave the Floating card visible.

   ```powershell
   $exe = (Resolve-Path 'build/release/qualification/Release/ClipRope.exe').Path
   $case = (New-Item -ItemType Directory -Path (Join-Path $env:TEMP ('cliprope-sleep-' + [guid]::NewGuid()))).FullName
   $store = Join-Path $case 'store'
   $receipt = Join-Path $case 'receipt.txt'
   $app = Start-Process -FilePath $exe -ArgumentList @('--show','--profile',('"' + $store + '"'),'--probe',('"' + $receipt + '"')) -PassThru
   Get-FileHash -Algorithm SHA256 $exe
   ```

2. Immediately before the user chooses **Start → Power → Sleep**, run `$since = Get-Date` in the same PowerShell session. Wake and unlock the PC when convenient. Query the System log for this interval and inspect the messages for entry into sleep/Modern Standby and subsequent exit. Record the time, provider, event ID and record ID for both transitions. If only screen-off, lock or unlock is evidenced, leave hardware sleep unverified. On S0 hardware an existing SleepStudy report that identifies a matching **Sleep** interval can corroborate the event pair. [Microsoft SleepStudy reference](https://learn.microsoft.com/en-us/windows-hardware/design/device-experiences/modern-standby-sleepstudy)

   ```powershell
   Get-WinEvent -FilterHashtable @{LogName='System'; StartTime=$since; ProviderName=@('Microsoft-Windows-Kernel-Power','Microsoft-Windows-Power-Troubleshooter')} |
       Sort-Object TimeCreated | Format-List TimeCreated,ProviderName,Id,RecordId,Message
   ```

3. Verify `$app.HasExited` is false, the workspace remains hidden, and the seed Floating card is visible. Drag its body a short distance within the work area and require `move-floating <same-id> committed` in the receipt. In Notepad, type and copy only `ClipRope after wake` once. Allow five seconds, then reopen the workspace. Require one Hanging card showing that text, the seed still Floating, and exactly two admission receipts in the entire run (one seed and one post-wake entry, each with a distinct ID).

   ```powershell
   Get-Content -LiteralPath $receipt | Select-String '^power |^capture (captured|partial) [0-9a-f]+|^detach |^floating |^move-floating '
   ```

4. Exit via the candidate's tray menu, then run the following independent checks. Expect exit code zero, successful store verification and exactly one durable row in each state. Record the executable hash, Windows build, event pair and test outcome. After saving this evidence, delete only the generated `cliprope-sleep-<GUID>` test directory.

   ```powershell
   $app.WaitForExit()
   $app.ExitCode
   & (Join-Path (Split-Path $exe) 'cliprope_headless.exe') $store verify
   python -c "import sqlite3,sys; from pathlib import Path; db=sqlite3.connect(Path(sys.argv[1]).resolve().as_uri()+'?mode=ro',uri=True); rows=db.execute('select state,count(*) from entries group by state').fetchall(); print(rows); assert dict(rows)=={'Floating':1,'Hanging':1}" (Join-Path $store 'history.db')
   ```

### Waiting for a natural sleep on an isolated clipboard

For a window-station test without interactive input, reserve the project's noninteractive test station and run the following foreground command from the repository root. The timeout in seconds must be between 1 and 86400. This command is separate from CTest. The station launcher serializes private-clipboard users, so run the ordinary clipboard suites before or after the reserved interval. The reference machine's AC policy allowed neither automatic display-off nor automatic sleep at qualification time.

```powershell
$bin = (Resolve-Path 'build/release/qualification/Release').Path
$since = Get-Date
& "$bin/cliprope_station_test.exe" "$bin/cliprope_desktop_notifications.exe" --await-natural-resume 3600 "$bin/ClipRope.exe" "$bin/cliprope_ole_source.exe"
$LASTEXITCODE
```

The command leaves power policy and sleep timing to Windows. The fixture opens a synthetic profile on its private desktop, verifies a successful subscription and waits without sending input or power messages. After the candidate records an ordered suspend/resume pair, a separate producer publishes one synthetic Unicode/HTML copy on that station. The fixture checks the original Floating HWND geometry and identity, the hidden workspace, one durable new entry with the expected bytes, and clean shutdown. It prints `suspend_utc_filetime` and `resume_utc_filetime`. Convert each value with `[DateTime]::FromFileTimeUtc([long]$value)` and corroborate the interval with the System events in step 2 before recording a physical sleep pass. This station can verify HWND geometry. The interactive procedure additionally verifies visible pixels and real input.

Exit code zero records a qualifying message pair and the application checks. Code 3 means the deadline passed without an observed pair in the interval. A one-second timeout run was verified to exit cleanly and publish zero samples. Any other nonzero result reports a fixture or application failure. A sleeping machine observes timeout on its next wake.

On 2026-11-01 the release qualification build also waited for 600 seconds, approximately 03:10–03:20 local time. It reported `natural_resume=timeout qualifying_power_pair=0 external_copies=0` and exited with code 3. The Windows System log contained no Kernel-Power events 42, 107, 506 or 507 during the observation window. The fixture processes exited and the temporary profile was removed.

The first manual S0 cycle on November 1 produced Kernel-Power event 506 (record 204238, 09:02:10 local) and event 507 (record 204240, 09:02:22). The candidate recorded suspend and resume at UTC FILETIMEs `134379685308206441` and `134379685422886409`. The original Floating window remained reachable and the workspace stayed hidden. The independent producer then received `CLIPBRD_E_CANT_OPEN` on its first publication attempt and exited before publishing. This run verified the power transition and layout. It supplied no post-wake capture result.

The post-resume producer now retains its data object and retries a failed clipboard open for up to two minutes. A known change to the original sequence or any other publication error ends the attempt. The normal session-notification regression holds the isolated clipboard open for 250 ms in another process. Three consecutive runs reported 3, 4 and 4 attempts, one successful publication and one durable new entry each. The release application and installer were unchanged.

On November 1 the contributor again slept and woke the machine manually. The private-station probe from `e4fdd10` monitored the same probe-enabled Release candidate (SHA-256 `c64cb5e697e97f622183039ecd3d679bec4c84220605bd4a6676f619c46aa2da`). The Windows System log and the resident receipt agreed on the following transition. Times are local (UTC+08:00).

| Transition | Microsoft-Windows-Kernel-Power | Event record | Event time | Resident UTC FILETIME |
| --- | ---: | ---: | --- | ---: |
| Enter Modern Standby | 506 | 204245 | 09:05:13.203 | 134379687132663755 |
| Exit Modern Standby | 507 | 204247 | 09:05:20.874 | 134379687205671150 |

The workspace stayed hidden. The original Floating HWND retained its visible window style and stayed within the work area. A separate producer published on its first attempt. After normal shutdown and removal of the power subscription, the fixture reopened the database. The original Hanging and Floating IDs survived alongside exactly one new Hanging entry whose Unicode bytes matched the external sample. The probe exited with code 0.
