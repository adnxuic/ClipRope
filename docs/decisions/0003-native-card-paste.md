# ADR 0003 · Native paste on card activation

**Accepted.** This decision revises the delivery mechanism and sequencing in [ADR 0001](0001-card-double-click.md). The native paste contract now applies to Hanging cards. [ADR 0008](0008-floating-double-click.md) supersedes the original Floating behavior below.

1. Bind the external editor before the press takes focus. At double-click confirmation, bind the Floating return rope. Discard canceled gestures. The binding lives only in memory.
2. Publish the recoverable snapshot with its lease and suppress its self-update. Publication failure ends the command without changing history, windows or input.
   A confirmed Hanging invocation queued behind an accepted capture also binds the current clipboard sequence. If an external copy replaces it before publication, cancel the queued invocation and preserve the newer external offer. The canceled command performs no promotion and sends no shortcut. Once publication has succeeded, history and delivery retain their separate outcomes below.
3. Attempt the existing history transaction. On commit, promote Hanging on its own rope or rehang Floating at the head of the bound rope, evict its old tail as needed, retire the returned window and collapse the workspace. Failure preserves prior durable and visible state.
4. The Cards preference fixes the delivery mode when a Hanging double-click is confirmed. Copy only skips native delivery, including to Explorer. Both modes retain the publication and promotion steps above. In the default copy-and-paste mode, independently attempt delivery. Restore the original window only if ClipRope interrupted its focus. Check the foreground, thread, process, writable field or Office selection, permissions, modifier state and identity of this particular publication. A failed preflight consumes the gesture without input.
5. Send Ctrl down, V down, V up and Ctrl up as one batch. Record a full batch as **shortcut_sent**, a rejected batch as **send-failed**, and partial dispatch as **unconfirmed**. Release any outstanding injected keys after partial dispatch. Never send a second paste for the gesture.

Explorer folder targets follow the [folder paste decision](0005-explorer-folder-paste.md). Image file references use the editor checks in [ADR 0004](0004-image-file-previews.md). Other successfully published snapshots use the following delivery path. ClipRope verifies the editor and sends one shortcut regardless of which formats are present. This includes images, real and virtual file groups, and HTML-only links. An application can handle paste in an ordinary-looking field or ignore everything offered. A complete shortcut batch has the same meaning in either case.

Standard Win32 edits, writable UI Automation Edit values and writable text selections accept the existing editor payloads. An Excel document pane binds its workbook, worksheet, complete selected range and active cell, including merged selections. A PowerPoint editing pane binds its presentation, pane and current slide or selected slides. Shape IDs and the text selection within its owning shape distinguish destinations that share the same HWND. Read-only documents, locked worksheet ranges and changed selections suppress automatic paste.

For a publication consisting entirely of Unicode text, HTML or RTF, a focused Group, Document or Custom element with a writable value also qualifies. A custom surface that supplies insufficient editing information can receive this text at its original native keyboard focus. Bind the external foreground window, focus HWND, thread, process and any available UI Automation element before ClipRope takes focus. Recheck them immediately before dispatch. A verified binding must retain its editing capability. A different or disappeared bound element cancels the gesture. When several internal editors share an HWND and expose no distinct identity, their host resolves the internal destination.

Disabled, password, read-only and recognized command controls receive no shortcut. Mixed image/text and file offers require their existing destination checks. Qualification receipts record the target decision and UI Automation control type separately from focus restoration, publication, history commit and shortcut dispatch.

The receiving editor chooses a representation. The clipboard remains available for manual paste until another writer replaces it. Tray and rope-head activation publish for manual paste. Returns and dragging can publish a changed collector head for manual paste under [ADR 0024](0024-collector-head-clipboard.md). Existing profiles require no migration.

The old native Edit and Edge adapters wrote Unicode directly to a bound field. Native paste allows Word to select rich text and Excel to distribute tabular data. Windows confirms queue insertion only. A delayed consumer can resolve a different focus or read a subsequent copy after dispatch. The recorded Edge experiment delivered the newer text to field B after binding field A. This is an accepted boundary. Report what the consumer did only when independently observed.
